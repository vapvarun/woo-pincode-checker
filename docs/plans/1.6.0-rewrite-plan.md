## 1. Positioning

- The free niche is small and winnable: the largest live wp.org pincode plugin has 600 installs. Three competitors were closed by wp.org (one for security), so trust is an open lane.
- Demand is India-led (6-digit PIN, COD), but UK/US/EU stores keep hitting postal-format bugs. That is the top complaint.
- No WooCommerce competitor claims Blocks checkout support, or combines serviceability with a real delivery-date engine.
- Pitch: **"The pincode checker that works with any postal format, any theme, the Blocks checkout and page caching - and tells customers when it will arrive."**

## 3. Principles

1. **Layered.** Bootstrap -> Container -> Repository -> Services -> Surface adapters (REST, CLI, blocks, shortcodes, WooCommerce hooks) -> Templates -> Admin UI. Lower layers never depend on higher ones. Only repositories touch `$wpdb`.
2. **Areas are rules, not rows.** Exact code, prefix/wildcard (`SW1*`, `110***`) or numeric range. A range is one row, never expanded.
3. **Normalise everything** with `wc_normalize_postcode()`; validate per country with `WC_Validation::is_postcode()`.
4. **Cache-safe storefront.** Static form + read-only REST lookup with no nonce, so cached pages never break. The saved pincode is a first-party cookie + localStorage, read in JS.
5. **Server enforces, JS decorates.** Add-to-cart, checkout, COD and shipping are enforced in PHP.
6. **Big-site ready from day one.** 100k+ areas: indexed lookups, cursor-safe pagination, background import/export, cached aggregates.
7. **One source of truth.** One normaliser, one matcher, one settings schema, one checker renderer for the product hook, shortcode and block.
8. **Wbcom UX foundation.** Tokens only, Lucide icons, logical CSS properties, 390px, WCAG 2.1 AA, no inline `<style>`/`<script>` in PHP, no `alert()`/`confirm()`, no admin-ajax.
9. **PHP 8.1-8.5**, WP 6.5+, WC 8.0+, `declare(strict_types=1)` in every class file.

## 5. Domain model

| Concept | Meaning |
|---|---|
| **Service area** | One rule saying whether, how fast and at what cost we deliver to a set of postcodes: exact (`110001`), prefix (`SW1*`, matches `SW1A 1AA`) or numeric range (`110001`-`110099`). Country-scoped or "any country". |
| **Status** | `serviceable` or `blocked`. Blocked lets a store carve exceptions out of a prefix or range. |
| **Unknown postcode policy** | What happens when no area matches: `unavailable` (default, whitelist stores) or `available` with default terms (blacklist stores). |
| **Check result** | `{ status: available/unavailable/invalid, area_id, postcode, country, city, state, cod: {allowed, fee}, shipping_fee, estimate: {min, max, label}, nearby: [] }` - the single object every surface (REST, product page, cart, checkout, CLI, tester) uses. |
| **Delivery estimate** | From the engine: store rules (processing, cut-off, working days, holidays) + area days + category extra days. |
| **Job** | A background import/export run with progress and a result report. |

Matching precedence: exact > longest prefix > narrowest range. A specific country beats "any". At equal specificity, blocked beats serviceable. Then the unknown policy.

Alternative considered: delivery "profiles" (zones holding the terms) with codes pointing at them. Rejected for 1.6.0: courier serviceability lists come per pincode with their own days/COD values, and bulk edit by filter covers "change terms for many areas" without a second table. Pro can add profiles later in its own table keyed by area id.

## 6. Database

All tables `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`, created with `dbDelta`, version-gated by `wpc_db_version`.

### 6.1 `{prefix}wpc_areas`
```sql
id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
country       CHAR(2)          NOT NULL DEFAULT '',      -- '' = any country
match_type    TINYINT UNSIGNED NOT NULL DEFAULT 1,       -- 1 exact, 2 prefix, 3 range
code          VARCHAR(20)      NOT NULL,                 -- as entered (range start)
code_to       VARCHAR(20)      NOT NULL DEFAULT '',      -- range end as entered
code_norm     VARCHAR(20)      NOT NULL,                 -- exact: normalised; prefix: prefix w/o *; range: ''
range_start   BIGINT UNSIGNED  NULL,
range_end     BIGINT UNSIGNED  NULL,
status        TINYINT UNSIGNED NOT NULL DEFAULT 1,       -- 1 serviceable, 0 blocked
city          VARCHAR(100)     NOT NULL DEFAULT '',
state         VARCHAR(100)     NOT NULL DEFAULT '',
days_min      SMALLINT UNSIGNED NULL,                    -- NULL = store default
days_max      SMALLINT UNSIGNED NULL,
shipping_fee  DECIMAL(12,4)    NULL,                     -- NULL = no area fee
cod_allowed   TINYINT UNSIGNED NOT NULL DEFAULT 1,
cod_fee       DECIMAL(12,4)    NOT NULL DEFAULT 0,
note          VARCHAR(255)     NOT NULL DEFAULT '',
created_at    DATETIME         NOT NULL,                 -- UTC
updated_at    DATETIME         NOT NULL,                 -- UTC
PRIMARY KEY  (id),
UNIQUE KEY area (country, match_type, code_norm, range_start),
KEY lookup (code_norm, match_type, country),
KEY lookup_range (match_type, range_start, range_end),
KEY state (state),
KEY updated (updated_at)
```
Lookup query (one round trip, all branches indexed):
```sql
SELECT * FROM wpc_areas WHERE match_type = 1 AND code_norm = %s AND country IN (%s, '')
UNION ALL
SELECT * FROM wpc_areas WHERE match_type = 2 AND code_norm IN (<every prefix of the code, longest first>) AND country IN (%s, '')
UNION ALL
SELECT * FROM wpc_areas WHERE match_type = 3 AND range_start <= %d AND range_end >= %d AND country IN (%s, '')   -- numeric codes only
LIMIT 50
```
Precedence is resolved in PHP over at most 50 candidate rows. Result cache: object cache group `wpc`, key `check:{areas_version}:{country}:{code}`, so any area write bumps `wpc_areas_version` and old entries simply expire.
Admin list: `LIMIT/OFFSET` over indexed sorts, max 100 per page; counts via `COUNT(*)` cached per filter + areas version.

### 6.2 Jobs: no table
One import runs at a time. Its state lives in option `wpc_job` (autoload no): `{ id, type, status, total, processed, added, updated, skipped, failed, file, error_file, args, message, user_id, started_at, updated_at }`. A finished job is appended to `wpc_job_history` (last 10, autoload no). No table, no pruning action. Files in `uploads/wpc-private/` are deleted when the next job starts or after 24h (checked on the next job start).

## 12. Delivery date engine (`DeliveryDateService`)
```
now      = clock()->now( wp_timezone() )
start    = today if now < cutoff and today is a working day and not a holiday, else the next working day
dispatch = start + processing_days working days (skip non-working days + holidays)
extra    = max category extra days (product) or max over cart items (cart/checkout)
min      = dispatch + (area.days_min ?? default_min) + extra    (business or calendar per transit_counting)
max      = dispatch + (area.days_max ?? area.days_min ?? default_max) + extra
label    = per display (date / range / days) with wp_date( date_format )
```
Filter `wpc_estimate`. The clock is injectable; `wp wpc self-test` covers before/after cut-off, Friday before a holiday, Sunday off, business vs calendar, and category extra days.

### 13.1 REST `wpc/v1`
| Route | Method | Permission | Purpose |

## 19. Decisions made during the build
