# Pincode Checker 1.6.0 - QA checklist

Use this to check the whole plugin against what 1.6.0 is meant to do. Each line has the expected result. Tick it when it matches; when it does not, note the step, the browser, the viewport and a screenshot on the Basecamp card.

1.6.0 is a fresh rewrite. Nothing from 1.5.x (settings, pincode table, admin pages) carries over, so test on a clean site.

## 0. Test setup

- [ ] WordPress 6.5+, WooCommerce 8.0+, PHP 8.1 or newer, `WP_DEBUG` and `WP_DEBUG_LOG` on.
- [ ] Two themes ready: **Storefront** (classic checkout shortcode) and **Twenty Twenty-Five** (Cart and Checkout blocks).
- [ ] Products: one simple, one variable (2+ variations), one in a category you will use for Category Rules, one virtual or downloadable, one external/affiliate.
- [ ] Payment: Cash on delivery enabled, plus one other method (e.g. Direct bank transfer).
- [ ] Users: an Administrator, a **Shop Manager**, a Customer, and a guest (private window).
- [ ] Install from the release zip, not from git.
- [ ] Watch `wp-content/debug.log` for the whole run. **Any notice, warning or error from woo-pincode-checker is a bug.**

## 1. Install, activate, plug and play

- [ ] Activating takes you to the plugin screen. The menu is under **WB Plugins > Pincode Checker** only (no second top-level menu).
- [ ] On a fresh install, with **no areas yet**, any product page shows the checker and any postcode reads as **available**. Orders go through. (Default "Postcodes with no area" = Automatic.)
- [ ] After adding the first serviceable area, postcodes that match no area read as **not available**.
- [ ] Without WooCommerce active, the plugin cannot be activated, and WordPress lists WooCommerce as required. While Pincode Checker is active, WooCommerce cannot be deactivated. No fatal error either way.
- [ ] Overview tab: Store status rows are correct (WooCommerce version, checkout type, delivery areas count, Pincode rate shipping status).

## 2. Admin access

- [ ] Administrator sees and saves every tab.
- [ ] **Shop Manager** sees the menu, can add/edit/delete areas, import/export and **save settings** (no "Sorry, you are not allowed" after Save).
- [ ] Customer cannot open the page or call `/wp-json/wbpc/v1/areas` (gets 401/403).

## 3. Service Areas list

- [ ] Add each test area above. Saving shows it in the list without a page reload.
- [ ] Validation: `11*0` (star not at the end), range `100` to `99999` (different lengths), range `200` to `100` (reversed) and a duplicate code are each refused with a clear message.
- [ ] Edit an area: the form fills in, changes save, the list updates.
- [ ] Delete one area: asks in-page (no browser popup), then removes it.
- [ ] Select several rows > **Delete selected** works. Selecting the page checkbox offers "select all matching". Deleting more than 100 asks you to type DELETE.
- [ ] Search (code or city), filters (type, status, COD, country) and Sort (newest, code, city, fastest delivery) all change the list. "Showing X-Y of Z areas" is correct. Paging works.
- [ ] Empty states: no areas at all, and a filter with no matches, each show a helpful message.
- [ ] Layout at **1440**, **1024** and **390** px: no clipped buttons, no horizontal page scroll. Under about 760 px of card width the rows turn into cards.

## 4. Import / Export

- [ ] **Download sample CSV** opens a valid file.
- [ ] Import the sample with **Upload and preview**: the first rows show, then the job runs in the background with a progress bar, and **Recent imports** shows added/updated/skipped/failed counts.
- [ ] Import a file with bad rows: the good rows import, and **Download rows that failed** lists each bad row with its reason.
- [ ] Existing codes > **Update them with the values in the file**: a file with only `code,days_min` changes days but **does not blank** other columns (city, fees).
- [ ] Existing codes > **Delete all current areas first** requires typing REPLACE, then only the file's areas remain.
- [ ] A blank `cod_allowed` cell means COD allowed; `no` means not allowed.
- [ ] Header aliases work: `pincode`, `postcode` or `zip` in place of `code`.
- [ ] Cancel a running import: it stops, and the history says Cancelled.
- [ ] Big file: 20,000+ rows import without a timeout (leave the tab open; it also continues via the background queue).
- [ ] **Export areas** > **Download CSV** downloads every area, or only those matching the Country / Type / Status chosen there. Re-importing the export in update mode changes nothing.
- [ ] A cell starting with `=`, `+`, `-` or `@` is exported with a leading `'` (spreadsheet formula protection).

## 5. Product page checker (shopper)

Do this on **both themes**, as a **guest** and as a **logged-in customer**.

- [ ] The checker shows above Add to cart (default). Each "Show the checker" option on the General tab moves it correctly. "Only where I add the block or shortcode" hides it until you add the **Pincode Checker** block or `[wbpc_pincode_checker]`.
- [ ] `110001` shows: delivery available to New Delhi, an estimate, the shipping fee and "Cash on delivery available".
- [ ] `110050` matches the `110*` prefix (2-4 days, 60 fee, COD with 30 fee).
- [ ] `110099` is **not available** (blocked beats the 110* prefix).
- [ ] `560001`: available, "Cash on delivery not available".
- [ ] `999999`: not available. With **Suggest nearby areas** on, served postcodes starting the same way are suggested where relevant.
- [ ] `ab`: shows the invalid pincode message.
- [ ] Pressing Enter in the field runs the check (it does not submit the add-to-cart form).
- [ ] **Change** clears the result. Reloading the page, or opening another product, remembers the pincode (cookie, "Remember the pincode for" days).
- [ ] Not shown on virtual/downloadable or external products, on a product with **Pincode checker** ticked (Edit product > Shipping tab: "Hide the pincode checker and skip delivery-area checks"), or in **Skip these categories**.
- [ ] Variable product: switching variations keeps the right Add to cart state.

### Add to cart behaviour (General tab)

Test each combination; this was a 1.5.x bug.

- [ ] Require a pincode check **off**, When you do not deliver there = **Disable**: Add to cart works before checking; after an unserved pincode it is disabled.
- [ ] Same with **Hide**: the button hides after an unserved pincode and comes back after a served one.
- [ ] Same with **Keep Add to cart, show a warning**: the button stays usable, with the warning.
- [ ] Require a pincode check **on**: Add to cart is unusable until a **served** pincode is checked, and the "Check required" message shows.
- [ ] Server side: with an unserved pincode saved, adding via a direct `?add-to-cart=ID` URL is refused with a notice (not only the JS).

## 6. Delivery dates

- [ ] The estimate follows the area's days, or the default days when the area has none.
- [ ] Processing days and the same-day cut-off shift the dates (check one order before and one after the cut-off time, in the site timezone).
- [ ] Unticking Saturday/Sunday and adding a holiday skips those days. "Calendar days" counts every day.
- [ ] Each "Show the estimate as" option (range, latest date, days) and date format displays correctly.
- [ ] "Show the estimate on" controls product page, cart/checkout shipping options, order details and emails independently.
- [ ] **Category Rules**: add +2 days for a category. A product in it shows 2 more days; a cart with it shows the larger value. Saving this tab **does not change or hide** anything on the General tab (1.5.x bug).

## 7. Cart and checkout

Do this on **Storefront (classic checkout)** and **Twenty Twenty-Five (Checkout block)**.

- [ ] Add a **Pincode rate** method to a shipping zone (WooCommerce > Settings > Shipping). At checkout it charges the area's shipping fee (plus base cost); for an area with no fee it uses "Fee when the area has none".
- [ ] Shipping options show the delivery estimate next to the name. The completed order shows the plain method name, and the estimate separately in order details, admin order and email.
- [ ] Guest who checked `110001` on a product: checkout starts with that postcode filled in, and "Use same address for billing" stays ticked.
- [ ] Checkout with `110099` or an unserved postcode is **refused** with a clear message (Block orders to areas you do not serve = on). Turn the setting off: the order goes through.
- [ ] COD: hidden for `560001`, offered for `110001`. Choosing COD for `110001` adds "Cash on delivery fee" 25, and switching to another method removes it. Totals in the order match what checkout showed.
- [ ] Changing the postcode at checkout updates shipping, COD and the fee without a page reload.
- [ ] HPOS on and off: orders save the estimate and show it in admin.

## 8. Display and Messages tab

- [ ] Every label and message change shows on the storefront. `{postcode}`, `{city}`, `{state}`, `{estimate}`, `{amount}` are replaced.
- [ ] Emptying a message restores its default on save.
- [ ] Colours: "Match my theme" vs "Use my accent colour" with a custom accent.
- [ ] The checker in dark mode matches the theme (only when the theme itself is dark).

## 9. Tools, FAQ, uninstall

- [ ] Tools > System status is correct. **Update database** and **Clear lookup cache** each confirm success.
- [ ] Uninstall with "keep data" **off**: delete the plugin, then the `wbpc_areas` table, `wbpc_*` options and the private upload folder are gone. Past orders keep their saved estimate.
- [ ] Uninstall with "keep data" **on**: data stays; reinstalling shows the same areas and settings.

## 10. Caching, speed, big site

- [ ] With a page cache (WP Super Cache or similar) on, two different visitors checking different pincodes each see **their own** result, and the cached product page HTML has no pincode in it.
- [ ] Seed 100,000 areas (`wp wbpc seed 100000`): the Service Areas list, search and filters respond in about a second; product page checks stay instant.
- [ ] Hammering the check (60+ requests a minute from one IP) returns "too many requests" instead of slowing the site.
- [ ] `wp wbpc self-test` reports all checks passed.

## 11. Cross-cutting

- [ ] Every admin tab and the storefront checker at **390 px**: nothing clipped, no horizontal scroll.
- [ ] RTL (Settings > General > Site Language: Arabic): admin and checker mirror correctly.
- [ ] Keyboard only: you can reach and use every field, button, filter and row action; focus is visible.
- [ ] Runs alongside **Woo Custom My Account Page**: both admin screens look right under WB Plugins.
- [ ] No JavaScript errors in the browser console on any admin tab, product, cart or checkout page.
